# P03-G1 — Control de publicación

Veredicto **PASS_WITH_LIMITATIONS**. Gate implementado en archivos propios de Estadísticas; cierre default y denegaciones verificados offline, sin habilitar configuración real, iniciar servidor ni conectar bases. QA real con cookies y publicación habilitada sigue pendiente.

Publicación y autorización son controles distintos. verifyStatisticsPrincipal sigue verificando getUser y profiles originales; owner/manager/admin exclusivamente, sin NULL/unknown/super_admin. Después se evalúa publicación con el mismo scope que precede a la RPC. Auth/rol denegados mantienen401/login y403; fallos de infraestructura conservan error. Período inválido conserva400. No se creó un segundo principal entre publicación y lectura que pudiera seleccionar otro negocio.

Página /admin/statistics: not_published→notFound, sin componente ni consulta. Endpoint:404genérico, private/no-store/Vary Cookie, sin datos ni RPC cuando no publicado. readAuthenticatedSummary ahora cierra también por defecto si no recibe política explícita de servidor. summary-server suministra la política privada; no cambia firmas SQL ni la respuesta financiera exitosa. El navegador no puede conceder publicación medianteURL, menú o storage.

La única modalidad permitida es QA aislado. Variable privada ORDEROPS_STATISTICS_QA_PUBLICATION: JSON con claves exactas version,projectId,api,db,principals. version=statistics.qa-publication.v1; proyecto=orderops-statistics-v1-test-74718de66a41; API=http://127.0.0.1:56321; DB=127.0.0.1:56322; hasta12parejas UUID userId/businessId. El cliente SSR debe tener realmente supabaseUrl con ese origen y sin path/query/credenciales; inspección del SDK instalado confirma la propiedad runtime. No hay modo producción, wildcards, roles en config ni NEXT_PUBLIC de publicación. Config ausente/malformada/extra o target incorrecto cierra.

La configuración es confiable porque solo la aporta el operador del proceso servidor; no se deriva de request. El origen exacto y parejas verificadas acotan QA, pero no certifican por sí mismos identidad live del proyecto detrás de un puerto. **Antes de activar QA**, el launcher autorizado debe verificar adversarialmente proyecto/marker/ledger/recursos, fixtures exclusivamente sintéticos y correspondencia de parejas. No se generó ni instaló una configuración QA en esta fase. No se declara attestation criptográfica ni identidad live por leer un projectId de JSON.

Cambios propios: statistics-publication-policy.ts/server.ts nuevos; summary-route-server.ts,summary-server.ts,summary-transport.ts y página/endpoint existentes propios modificados. implementation.diff contiene antes/después completos; bytes anteriores se reconstruyen exactamente contra baseline previo.
